# تجهيز سيرفر مستقل

هذا الدليل للتنفيذ على VPS Linux تملكه. لا يوجد سيرفر مشتَرى أو منشور حاليًا. لا تحتاج أي كلمة مرور أو عنوان يخص TROLLMODZ. اختيار مزوّد وسعر يُحسم عند النشر، بعد موافقتك على التكلفة.

## المطلوب

1. VPS يدعم UDP، ونطاق مملوك لك يشير إليه مباشرة؛ لا تمرر بروتوكول Hysteria عبر CDN HTTP عادي.
2. Node.js 22.16+ من المصدر الرسمي، وNginx، وHysteria2 من إصدار رسمي ثابت ومتحقق من checksum. القوالب لا تنزل binaries أو تشغلها.
3. شهادة TLS صالحة للنطاق وتجديد تلقائي. استخدم نفس النطاق للويب والـVPN في القالب الأول.
4. افتح 80/TCP و443/TCP للويب و443/UDP للـVPN، وأبقِ SSH مقيدًا بعناوين الإدارة. منافذ 3000 و8081 و9999 تظل loopback ولا تُفتح في firewall.

## إعداد التطبيق

ضع نسخة نظيفة من ملفات المشروع في `/opt/phantom`، واستبعد `.git` وملفات البيانات القديمة والتقرير الداخلي وأي أسرار من الجهاز المحلي. أنشئ حسابي خدمة `phantom` و`phantom-vpn` بدون صلاحيات إدارة، وامنح الأول مجلد `data/runtime` فقط للكتابة. راجع مسار Node إذا لم يكن `/usr/bin/node`.

شغّل `npm run setup` في السيرفر لإنشاء أسرار مستقلة. عدّل `.env` محليًا على السيرفر، مع إبقاء الأسرار بعيدة عن المحادثة وGit:

```dotenv
NODE_ENV=production
HOST=127.0.0.1
PORT=3000
AUTH_PORT=8081
PUBLIC_URL=https://your-owned-domain.example
DATA_FILE=/opt/phantom/data/runtime/database.json
VPN_HOST=your-owned-domain.example
VPN_SNI=your-owned-domain.example
VPN_PORT=443
VPN_STATS_URL=http://127.0.0.1:9999
```

اترك قيم `ADMIN_TOKEN` و`APP_SECRET` و`VPN_STATS_SECRET` العشوائية التي ولّدها setup. اسم النطاق في المثال placeholder يجب استبداله. ملف `.env` يكون مملوكًا لمستخدم الخدمة بصلاحية 600.

شغّل:

```sh
npm test
npm run deploy:config
```

الأمر الثاني يكتب ملفات خاصة في `deploy/generated/` ولا يثبت خدمات:

- `hysteria.yaml` إلى `/etc/phantom/hysteria.yaml` بصلاحية 640 وملكية `root:phantom-vpn`.
- ملفا الخدمة إلى `/etc/systemd/system/` بعد مراجعة المسارات والملكية.
- إعداد Nginx إلى مجلد إعدادات المواقع وفق توزيعتك، بعد الحصول على شهادة صالحة.

ضع نسخة مقروءة فقط لحساب `phantom-vpn` من الشهادة والمفتاح في `/etc/phantom/tls/`. يجب أن يُحدّث hook تجديد الشهادة النسختين بصلاحيات محكمة ثم يعيد تشغيل خدمة VPN ويعيد تحميل Nginx. لا تمنح حساب بوابة الويب صلاحية قراءة المفتاح الخاص للشهادة.

تحقق من إعداد Nginx واختبر خدمات systemd على السيرفر قبل إتاحته للعملاء. شغّل portal ثم VPN ثم Nginx. تنشر هذه القوالب على جهاز Linux واحد؛ ليست ملف Docker مُختبرًا.

## حدود الوصول والقياس

- `/auth` موجود على خدمة منفصلة مربوطة بـ127.0.0.1 فقط. لا تعمل proxy لهذا المنفذ، ولا تسمح للـVPN بالوصول إلى loopback أو الشبكات الداخلية. قواعد ACL المولدة تمنع ذلك، بما فيها metadata/private/link-local ranges. تحقق من المنع على السيرفر الفعلي.
- API القياسات له سر مستقل ويبقى محليًا. لا تكشفه للعميل.
- رابط `/sub/...` يحمل صلاحية الاتصال؛ لا تسجله في logs أو analytics. قالب Nginx يعطل تسجيل الطلبات. راجع أي reverse proxy/CDN إضافي قبل استخدامه.
- تطبيق rate limiting الحالي يستخدم عنوان اتصال TCP مباشرة، ولا يثق بـX-Forwarded-For. خلف Nginx تُشارك الحدود بين المستخدمين؛ ضع حدودًا إضافية على Nginx واضبط تصميمها قبل إطلاق عدد كبير من العملاء، مع عدم تمرير رؤوس مزورة كتحديد للهوية.
- لا تعرض Ping خاص باللعبة؛ القياسات الحالية اتصالات وبايتات فقط. عدد الاتصالات في Hysteria ليس عدد مباريات أو عمليات TCP.
- عند تعطل التحكم في Hysteria، منع المصادقات الجديدة يظل قائمًا ما دام portal متاحًا؛ فصل الجلسات القائمة قد يتأخر حتى عودة API التحكم. يجب مراقبة هذه الحالة تشغيليًا.

## أول تجربة

افتح لوحة الإدارة عبر HTTPS، وأصدر مفتاحًا قصير المدة. افتح لوحة العميل على الهاتف، وأضف الاشتراك إلى Happ، ثم فعّل الاتصال من التطبيق. تأكد من أن الشهادة تُقبل بدون `insecure`، وأن المرور الفعلي وعداداته يتغيران، وأن الإلغاء يفصل الجلسة ويمنع إعادة الاتصال. أكمل خطوات `ACCEPTANCE.ar.md` قبل وصف المنصة بأنها جاهزة للإنتاج.
